## 4. Ответы на контрольные вопросы

### 1. Как отправить изменения на удаленный репозиторий?
**Ответ:** Командой `git push <имя_remote> <ветка>` (например, `git push origin main`). Флаг `-u` при первом вызове связывает локальную ветку с удаленной.

### 2. Как влить изменения в локальную ветку из удаленного репозитория?
**Ответ:** Командой `git pull <remote> <ветка>`. Команда совмещает в себе скачивание новых данных с сервера (`git fetch`) и их автоматическое слияние с текущей рабочей веткой (`git merge`).

### 3. Какой командой можно зафиксировать изменения в репозитории?
**Ответ:** Командой `git commit -m "Сообщение"`. Предварительно файлы индексируются командой `git add <файл>`.

### 4. Как используется GitHub в реальной работе?
**Ответ:**
1. Надежное хранение и резервное копирование кода.
2. Совместная работа нескольких разработчиков над одной кодовой базой.
3. Командное ревью кода (Code Review) через механизм **Pull Requests**.
4. Ведение задач, багов и спринтов через **Issues** и **Projects**.
5. Автоматизация сборки, тестирования и деплоя через **GitHub Actions** (CI/CD).

### 5. Опишите принцип коллективной работы с GitHub
**Ответ:**
1. Основная ветка `main` содержит проверенную версию проекта.
2. Под каждую задачу создается отдельная ветка (`git checkout -b feature-name`).
3. Разработчик делает коммиты локально и отправляет свою ветку в GitHub (`git push origin feature-name`).
4. На GitHub открывается **Pull Request** на слияние в `main`.
5. Коллеги смотрят код, комментируют, проходят автотесты.
6. После аппрува ветка вливается (`merge`) в `main`, остальные разработчики забирают обновление через `git pull`.
